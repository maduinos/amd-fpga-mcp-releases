How the server works

01 · MCP clientYour assistant sends structured requests over stdio.
02 · Tools & planningInspection, project plans, pinned toolchain selection and input checks.
03 · Job supervisorPersistent status, logs, cancellation, locks and artifact checks.
04 · Vendor tools / boardVivado, Vitis, XSDB and guarded target workflows.

Board profiles and bring-up plans are separated from generic tools. A plan does not execute hardware commands. Actual board support depends on its processor, memory, clocks, reset wiring, boot devices and validated artifacts.

Install and connect

Linux quick start

# Ubuntu 24.04 prerequisites
sudo apt install python3.12 python3.12-venv
tar -xzf amd-fpga-mcp-0.7.1-linux-x86_64.tar.gz
cd amd-fpga-mcp-0.7.1
bash install.sh

The installer checks bundle integrity, installs without downloading dependencies and performs an MCP handshake. It prints the executable path.

Windows quick start

# Administrator PowerShell; restart if requested
wsl --install -d Ubuntu-24.04
# Initialize Ubuntu, then install prerequisites
wsl -d Ubuntu-24.04 -- sudo apt install python3.12 python3.12-venv
# Extract the ZIP, open its bundle directory
powershell -ExecutionPolicy Bypass -File .\install.ps1

Check wsl --list --verbose: Ubuntu must use version 2. Keep development projects and AMD toolchains in the Linux environment.

MCP client configuration

Place this entry in your MCP client's server configuration. Replace <linux-user> with your actual Linux username. Configuration file location depends on your client.

Linux client

{
  "mcpServers": {
    "amd-fpga": {
      "command": "/home/<linux-user>/.local/share/amd-fpga-mcp/0.7.1/bin/amd-fpga-mcp",
      "args": []
    }
  }
}

Windows client

{
  "mcpServers": {
    "amd-fpga": {
      "command": "wsl.exe",
      "args": ["-d", "Ubuntu-24.04", "--",
        "/home/<linux-user>/.local/share/amd-fpga-mcp/0.7.1/bin/amd-fpga-mcp"]
    }
  }
}

Restart your client. Ask it to call get_server_info, inspect installed toolchains and list board profiles. Vendor tools may require their environment setup before starting the client; use Linux paths for all project and artifact arguments.

Updates and troubleshooting

How do I update or roll back?

Install the next release into its own version directory, then change the MCP client command. Older versions and job state are preserved. Roll back by restoring the old executable path.

The client cannot connect

Check the exact executable path, Python 3.12 and installer output. On Windows, initialize Ubuntu, confirm WSL version 2 and check the Linux username. The server uses stdio; do not add informational output to stdout in launch wrappers.

A vendor tool or board operation fails

Inspect the selected toolchain and job log first. AMD tools/licenses are external dependencies. Confirm Linux paths, target identity, hardware-server connection and the board-specific procedure. A successful software package test is not a hardware bring-up certificate.

Where are logs and state?

Persistent job state defaults to ~/.local/state/amd-fpga-mcp in Linux, including WSL. Set AMD_FPGA_MCP_STATE_DIR to choose another location. Keep credentials and private board data out of public issue reports.
